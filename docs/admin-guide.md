# 管理员使用和运维说明

这份文档给管理员和维护人员使用。内容包括题目、用户、考试、系统设置、备份、Docker Judge 检查和日常维护。

## 1. 如何登录后台

访问登录页：

```text
/login
```

使用管理员账号登录。登录成功后会进入：

```text
/admin
```

管理员首页包含：

- 题目管理
- 用户管理
- 题目练习
- 模拟考试管理
- 天梯排行榜
- 日常提交记录
- 考试提交记录
- 系统设置功能卡片

上线后必须修改默认管理员密码，不能继续使用 `admin123`。

管理员进入“题目练习”后，可以像学生一样打开题目详情并提交代码。题目详情页左上方提供“复制本题”按钮，会复制 Markdown 格式的完整题面，包含标题、难度、分类、题目描述、输入格式、输出格式、全部样例和数据范围，适合发给 GPT、备课或临时转发题目。学生端日常刷题详情和模拟考试答题页也提供相同按钮。

## 2. 如何新增题目

进入：

```text
/admin/problems
```

在右侧或页面表单中填写：

- 题型：编程题或选择判断题
- 标题
- 难度
- 分类
- 题目描述
- 输入格式
- 输出格式
- 样例输入
- 样例输出
- 数据范围
- 测试点列表

要求：

- 标题不能为空。
- 难度不能为空。
- 分类不能为空。
- 题目描述、输入格式、输出格式不能为空。
- 至少需要测试点。
- 至少需要两组样例测试点。
- 测试点输入和输出不能为空。

填写后点击“保存题目”。

选择“选择判断题”后，编程题输入输出和测试点表单会替换为小题编辑器。每道小题需要设置题干、选项、正确答案和正整数分值。判断题固定使用 A=正确、B=错误。

## 3. 如何编辑题目

进入：

```text
/admin/problems
```

题目列表中的“提交”数量是该题的日常刷题总提交次数。点击这个数字会进入：

```text
/admin/submissions?problemId=题目ID
```

进入后可以查看这道题的所有日常刷题提交记录。

在题目列表中找到题目，点击：

```text
编辑
```

修改表单内容后保存。

如果修改了分类，题目会移动到新的分类下，学生端和管理员端分类筛选也会自动更新。

## 4. 如何批量下架题目

进入：

```text
/admin/problems
```

使用方式：

1. 在题目列表左侧勾选要下架的题目。
2. 可以点击“全选当前页”。
3. 确认“已选择 N 道题”数量正确。
4. 点击“批量下架”。
5. 浏览器会弹出二次确认。
6. 确认后下架。

注意：

- 只会全选当前页，不会跨页全选。
- 切换分页或分类后，选中状态会清空。
- 下架题目会从日常题库、管理员校题、组卷和专项练习选题中隐藏，学生不能继续提交、试运行或使用 AI。
- 下架不会删除测试点、历史提交和考试关联，学生已经获得的天梯积分会保留。
- 已加入已发布考试或学生未完成专项练习的题目不能直接下架，应先处理对应考试或任务。

## 5. 如何通过 Markdown 导入题目

进入：

```text
/admin/problems/import
```

使用方式：

1. 上传 `.md` 文件，或直接粘贴 Markdown 文本。
2. 填写默认难度和默认分类，作为兜底。
3. 点击“解析预览”。
4. 检查题目标题、难度、分类、样例数量和数据范围。
5. 确认无误后点击确认导入。

导入成功后，题目会出现在日常题库中。

## 6. Markdown 标准格式

支持一个文件导入一道或多道题。每道题用一级标题 `#` 开始。

推荐格式：

````markdown
# A+B 问题

## 难度

入门

## 分类

基础语法

## 题目描述

输入两个整数 a 和 b，输出它们的和。

## 输入格式

一行两个整数 a 和 b。

## 输出格式

输出一个整数，表示 a+b 的结果。

## 样例

### 输入样例 1

```text
1 2
```

### 输出样例 1

```text
3
```

### 输入样例 2

```text
10 20
```

### 输出样例 2

```text
30
```

## 数据范围

1 <= a, b <= 1000
````

规则：

- 每道题至少两组样例。
- 输入样例和输出样例必须成对。
- 样例内容必须放在代码块中。
- 代码块里的内容才会保存为样例。
- `## 难度` 和 `## 分类` 可以在 Markdown 中写；如果缺少，则使用导入页面的默认值。
- 当前暂不支持在 Markdown 中设置隐藏测试点、考试分值或题目标签。

选择判断题使用 `## 题型` 和 `## 客观题`。选项必须是单行 `A. 选项内容`，不要写 `A.` 后再另起代码块：

````markdown
# GESP 选择判断标准样例

## 题型

选择判断

## 难度

入门

## 分类

GESP 一级

## 题目描述

请按题号顺序作答。

## 客观题

### 第 1 题

阅读下面代码，判断输出结果。

```cpp
int a = 3;
int b = 4;
cout << a + b << endl;
```

A. 输出 `7`
B. 输出 `34`
C. 编译错误
D. 没有输出

答案：A
分值：2

### 第 2 题

`break` 语句可以终止当前循环。（ ）

A. 正确
B. 错误

答案：A
分值：2
````

选择判断题不需要输入格式、输出格式和样例；每道小题必须有答案和正整数分值。题干可以使用 Markdown 代码块，做题页会渲染为代码样式，不显示原始 ```cpp 标记；选项里需要代码或输出时，用行内代码，例如 `A. 输出 \`7\``。

## 7. 如何创建模拟考试

进入：

```text
/admin/exams
```

点击新建考试，填写：

- 考试名称
- 考试说明
- 考试时长，单位分钟
- 考试类型：编程题考试或选择判断考试
- 考试状态
- 是否开启本场考试 AI 思路

建议新建时使用 `draft` 草稿状态，题目确认后再发布。

一场考试只能加入同类型题目。已有题目时考试类型会锁定；如需修改类型，先移除考试内全部题目。

考试 AI 开关只影响学生考试答题页。关闭时学生看不到 AI 按钮，接口也会拒绝请求；选择判断题默认不显示 AI，避免泄露客观题答案。

## 8. 如何添加已有题目到考试

进入考试编辑页：

```text
/admin/exams/[id]/edit
```

使用“添加已有题目”区域：

1. 可以直接点击分类按钮，只展示该分类下的题目。
2. 可以输入题目名称继续搜索。
3. 搜索结果中可以单独勾选题目。
4. 可以点击“全选当前结果”，一次性选中当前搜索结果中还没有加入考试的题目。
5. 设置题目分值。
6. 设置起始排序数字。
7. 点击“添加选中题目”，批量加入考试；也可以在某一道题右侧点击“添加到考试”单独加入。
8. 已经在考试中的题目会标记为“已在考试中”，不能重复加入。

已添加的题目会显示在当前考试题目列表中。

题目搜索会自动限制为当前考试类型。选择判断考试的题目总分由各小题分值合计，不在组卷页手动改分。

## 9. 如何通过 Markdown 导入题目到考试

进入：

```text
/admin/exams/[id]/import
```

使用方式和日常题库 Markdown 导入类似。

导入后：

- 题目会保存到日常题库。
- 测试点会保存到数据库。
- 题目会自动加入当前考试。
- 多题 Markdown 会一次加入多道题。

## 10. 如何发布考试

在考试管理页或考试编辑页点击发布。

发布前系统会校验：

- 考试标题不能为空。
- 考试时长必须大于 0。
- 考试至少包含 1 道题。
- 每道题必须有分值。
- 每道题分值必须大于 0。

考试状态说明：

```text
draft      草稿，学生不可见
published  已发布，学生可参加
ended      已结束，学生不可继续答题
```

管理员可以在模拟考试列表中点击“进入做题”，按考试题单逐题检查题面并提交代码或选择判断答案。管理员练习模式不限时，不需要交卷，提交记录计入日常提交，不会创建学生考试记录或影响考试成绩。单大题选择判断练习会隐藏左侧题单以扩大题面；同场多题时仍保留题单用于切题。管理员练习页会展示选择判断小题的标准答案，方便老师校题；学生端不会展示标准答案。代码编辑器与学生端一致，已关闭自动代码提示、Tab 补全、参数提示和内联建议，并支持代码字号调节。提交 Accepted 后会短暂显示透明背景通过提示图。

## 14. 如何修改系统设置

进入：

```text
/admin/settings
```

可以修改：

- 平台名称
- 平台副标题
- 浏览器标签名称
- 浏览器标签图标
- 学生端公告
- 管理员端公告
- 默认 C++ 代码模板
- 默认评测时间限制
- 默认评测内存限制
- 日常练习 AI 思路开关
- 是否允许学生自助注册

注意：

- 默认时间限制必须大于 0。
- 默认内存限制必须大于 0。
- 默认 C++ 模板不能为空。
- 浏览器标签名称最多 60 个字；留空时自动使用平台名称。
- 浏览器标签图标只支持 PNG、ICO，最大 256KB，建议使用 64×64 或 128×128 的正方形图片；点击“恢复默认图标”可清空自定义图标。
- 保存后当前浏览器标签立即更新，其他已经打开的页面刷新后生效。
- 日常练习 AI 关闭时，学生刷题页不显示 AI 按钮，接口也会返回 403。
- 当前暂未开放学生自助注册页，注册开关是预留设置。

### AI 助手开关

- 日常练习 AI 开关在“系统设置”中全局控制。
- 考试 AI 开关在考试新建/编辑表单中按单场考试控制，默认关闭。
- 每名学生还需要在“用户管理”中单独开通“AI 对话权限”，个人权限默认关闭。
- 学生个人权限和日常/考试开关必须同时开启；任一关闭时学生页面隐藏 AI，接口也会返回 403。
- AI 只支持编程题；选择判断题不显示 AI 按钮。
- AI 提供理解题目、下一步提示、检查当前代码和当前题目自由追问，但不能返回完整代码、可复制代码语句或最终答案。
- 同一学生在所有题目、考试和 AI 入口中共用 20 秒冷却，由服务端强制限制，不能通过切换按钮、题目或考试绕过。
- 对话只保存在学生浏览器中，管理员端不查看、不保存学生 AI 对话；代码快照也不写入对话记录。

## 15. 如何备份 SQLite 数据库

正式使用期间建议每天至少备份一次。

Windows：

```bash
npm run backup:sqlite
```

Linux：

```bash
bash scripts/backup-sqlite.sh
```

备份文件会生成到：

```text
backups/
```

文件名类似：

```text
dev-YYYYMMDD-HHMMSS.db
```

备份完成后，建议确认备份文件存在并且大小不是 0。

## 16. 如何检查 Docker 是否正常

执行：

```bash
docker --version
docker info
```

如果 `docker --version` 正常，但 `docker info` 失败，说明 Docker CLI 已安装，但 Docker Desktop 或 Docker Engine 没有启动。

还可以检查 Judge 镜像：

```bash
docker images oj-cpp-judge
```

如果镜像不存在，重新构建：

```bash
docker build -t oj-cpp-judge ./docker/judge-cpp
```

## 17. 如何检查 `/api/health`

服务启动后访问：

```text
/api/health
```

正常返回示例：

```json
{
  "ok": true,
  "database": "ok",
  "timestamp": "2026-05-06T00:00:00.000Z"
}
```

检查重点：

- `ok` 应该是 `true`。
- `database` 应该是 `ok`。
- 健康接口不展示 Judge 模式；正式使用时请通过 `.env` 或 `npm run check:env` 确认 `JUDGE_MODE=docker`。
- 返回中不应该包含密码、SESSION_SECRET 等敏感信息。

## 18. 如何处理 Docker Judge 异常

管理员题目练习和管理员考试练习中的编程题也提供“运行样例 / 自定义输入”。试运行不会写入 `Submission`，不会改变排行榜、错题本、考试成绩或专项练习进度。上线或上课前建议先运行一个公开样例和一个自定义输入，再执行一次正式提交，分别确认试运行和正式判题都正常。

试运行与正式提交共用 Judge 队列，但正式提交优先于尚未开始的试运行。每个账号只能同时进行一个试运行，结束后有 5 秒冷却；频繁点击会返回 429，不代表 Docker 损坏。

若只有“运行样例”不可用而自定义输入正常，先检查题目是否配置了公开样例。样例输入和标准输出只由服务端读取，管理员和学生浏览器都不能自行传入隐藏测试点。

### 学生提交一直失败

先检查 Docker：

```bash
docker info
```

再检查健康接口：

```text
/api/health
```

确认 `.env` 中：

```env
NODE_ENV=production
JUDGE_MODE=docker
JUDGE_DOCKER_IMAGE=oj-cpp-judge
```

### Docker Judge 不工作

检查容器和镜像：

```bash
docker ps
docker ps -a
docker images
```

重新构建镜像：

```bash
docker build -t oj-cpp-judge ./docker/judge-cpp
```

然后重启服务。

### Docker daemon 没启动

表现：

```text
docker info
```

报无法连接 Docker API。

处理：

- Windows：启动 Docker Desktop。
- Linux：启动 Docker Engine。

### Time Limit Exceeded 很多

可能是：

- 学生代码死循环。
- 题目时间限制太小。
- 服务器资源不足。

可在 `/admin/settings` 中检查默认评测时间限制。

## 19. 数据库误操作怎么办

如果误删题目、用户或考试：

1. 先停止服务。
2. 按时间戳找到本次误操作前生成的备份文件：

```text
backups/
```

3. 用备份数据库替换当前 SQLite 数据库。
4. 重新启动服务。
5. 检查 `/api/health`。

恢复前建议把当前数据库也复制一份，避免二次损坏。

## 20. 复制代码失败怎么办

如果管理端或学生端点击“复制代码”后显示失败，优先检查访问地址是否仍是公网 HTTP。现代浏览器在非安全上下文中会禁用 `navigator.clipboard.writeText`。

当前平台已经增加兼容复制方案：HTTPS 或安全上下文优先使用 Clipboard API，公网 HTTP 下 fallback 到 `textarea + document.execCommand("copy")`。如果线上仍然失败，按下面顺序检查：

```bash
grep -n 'execCommand\|isSecureContext' /www/oj/src/lib/copyToClipboard.ts
pm2 stop oj
NEXT_TELEMETRY_DISABLED=1 NEXT_PRIVATE_BUILD_WORKER_COUNT=1 NODE_OPTIONS='--max-old-space-size=768' npm run build
pm2 restart oj --update-env
curl http://127.0.0.1:3000/api/health
```

长期建议仍然是绑定域名并配置 HTTPS。

## 22. 如何管理学生头衔和天梯榜

进入：

```text
/admin/leaderboard
```

管理员天梯榜顶部展示前三名领奖台，第四名以后展示完整排名。电脑端使用数据表，移动端使用纵向卡片；管理员仍可查看头衔来源、展示头衔、自动段位、段位积分、唯一 AC 题数和 AC 总次数。

当前计分规则：

- 段位积分实时从历史 `Submission` 计算，不写入积分缓存表。
- 每个学生每道题第一次 Accepted 计入唯一 AC 题数，并获得 10 段位积分。
- 同一题多次 Accepted 只算 1 道唯一 AC 题，但会计入 AC 总次数。
- 日常刷题提交和模拟考试提交都会计入统计。
- 排名排序为：段位积分降序 → 唯一 AC 题数降序 → AC 总次数降序 → 用户名升序 → 用户 ID 升序。

如需设置学生自定义头衔，进入：

```text
/admin/users
```

在新增或编辑学生账号时，可以填写“自定义头衔”并开通“AI 对话权限”。头衔最多 20 个字，留空则使用系统根据积分计算出的自动段位名；自定义头衔只影响展示文案，不影响段位积分、自动段位和排名。AI 权限默认关闭，并且还要同时开启日常练习 AI 总开关或对应考试 AI 开关才能使用。

## 23. 如何使用教师学情看板和下发专项练习

进入：

```text
/admin/learning
```

看板会汇总所有学生近 7 天、近 30 天或全部历史的编程提交。日常练习和考试都会参与诊断；选择判断题不会混入。点击学生后可以查看分类掌握率、错误状态、持续卡题和最近失败提交。

“AI 学情摘要”只把提交数量、错误分布、薄弱分类、持续卡题和题库缺口等聚合统计发送给 DeepSeek，不发送源码、隐藏测试点、完整错误日志或学生 AI 对话。相同数据会复用数据库缓存；AI 失败时仍可正常查看规则诊断和下发练习。

下发流程：

1. 核对系统推荐题。推荐优先使用待攻克错题，再补充同分类从未尝试题。
2. 根据需要删除、搜索添加或调整顺序，每份选择 1–10 道编程题。
3. 填写标题、可选说明和截止日期，然后确认下发。
4. 下发后题目集合不再修改；标题、说明、截止日期可编辑。进行中任务需先归档，归档后可永久删除，删除操作不可恢复。

同一道题不能同时出现在该学生两份未完成任务中。只有学生从专项练习入口进入并重新提交 `Accepted` 才计入完成；普通日常提交、考试提交和下发前的历史 AC 均不抵扣。若显示题库缺口，点击“新增该分类题目”会打开新增编程题表单并预填分类。

## 26. 常用命令

安装依赖：

```bash
npm install
```

本地构建：

```bash
npm run build
```

常规发布优先参考 `docs/deploy.md`，在本地 Linux/Docker 环境生成 standalone 包后上传。只有必须在 2 核 2GB 服务器上构建时，才使用下面的低内存兜底命令：

```bash
pm2 stop oj
NEXT_TELEMETRY_DISABLED=1 NEXT_PRIVATE_BUILD_WORKER_COUNT=1 NODE_OPTIONS='--max-old-space-size=768' npm run build
pm2 restart oj --update-env
curl http://127.0.0.1:3000/api/health
```

启动生产服务。`npm run start` 会先检查生产环境变量、预加载 `.env`，再启动 standalone 服务；不要绕过它直接裸跑 standalone server。

```bash
npm run start
```

检查生产环境变量：

```bash
npm run check:env
```

应用数据库迁移：

```bash
npm run db:deploy
```

查看迁移状态：

```bash
npm run db:status
```

修改管理员密码：

```bash
npm run admin:password -- admin 新密码
```

备份数据库：

```bash
npm run backup:sqlite
```

运行质量检查：

```bash
npm run test
npx tsc --noEmit
npm run lint
npm run build
```
