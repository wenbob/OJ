# 管理员使用和运维说明

这份文档给管理员和维护人员使用。内容包括题目、用户、考试、系统设置、备份、Docker Judge 检查和日常维护。老师的日常操作见 [老师端使用说明](teacher-guide.md)。

## 1. 如何登录后台

访问登录页：

```text
/login
```

使用管理员账号登录。登录成功后会进入：

```text
/admin
```

管理员首页包含：

- 题目管理
- 用户管理
- 题目练习
- 模拟考试管理
- 天梯排行榜
- 日常提交记录
- 考试提交记录
- 系统设置功能卡片

上线后必须修改默认管理员密码，不能继续使用 `admin123`。

管理员进入“题目练习”后，可以像学生一样打开题目详情并提交代码。当前管理员账号只要曾经通过某道题，题目列表和详情会持续显示“已通过”，以后提交失败也不会取消。标签旁的“查看通过代码”或“查看通过答案”会打开该管理员最近一次 Accepted 的提交详情。题目详情页左上方还提供“复制本题”按钮，会复制 Markdown 格式的完整题面，包含标题、难度、分类、题目描述、输入格式、输出格式、全部样例和数据范围，适合发给 GPT、备课或临时转发题目。学生端日常刷题详情和模拟考试答题页也提供相同按钮。

管理员提交选择判断答案后，答案区会立即展开每一道小题的正确或错误和本次填写的答案，并提供完整提交详情入口。该结果不会自动展开标准答案；标准答案仍由题目标题旁的统一显隐按钮控制。

开启“选择判断题 AI 解析”后，管理员题目练习中的每道选择判断小题旁会显示“AI 解析”。右侧上方显示整体思路、正确选项依据、各错误选项原因和知识点，下方保留答案输入与提交。解析由学生、老师和管理员共享，三种角色都可以按各自间隔确认后重新生成；成功后覆盖共享版本，失败时保留旧解析。学生只有在学生总开关、个人选择判断权限均开启且当前大题至少提交过一次日常答案后，才能在日常刷题或专项练习中逐题查看；正式考试不开放。

管理员题目管理和题目练习默认每页展示 50 道题；日常提交、考试提交和考试记录仍默认每页展示 20 条。

### 创建和维护老师账号

进入 `/admin/users`，选择 `teacher` 角色即可创建老师。只有管理员可以查看、创建、改密、改角色或删除老师和管理员账号。

老师登录后进入独立 `/teacher`，可以校题、管理学生、使用现有题库组卷、管理自己创建的考试，以及维护自己下发的专项练习；老师不能访问系统设置、AI 模型配置、题目管理、题目导入、上下架、排序或考试 Markdown 导入。

老师端学生管理只允许查看和新增学生、分别切换编程 AI 与选择判断 AI 权限，以及把密码重置为固定初始值 `12345678`。老师还可搜索、勾选、全选当前搜索结果并批量开关选择判断 AI。老师不能修改学生用户名、角色或自定义头衔，也不能删除学生；这些完整账号维护能力继续只属于管理员。

历史考试没有创建者，只允许管理员管理。新考试会自动记录创建账号；管理员可以管理全部考试，老师只能管理自己的考试。删除老师会保留其考试并清空创建者；把老师改为学生时也会清空其考试归属，同时废除旧会话。

## 2. 如何新增题目

进入：

```text
/admin/problems
```

在右侧或页面表单中填写：

- 题型：编程题或选择判断题
- 标题
- 难度
- 分类
- 题目描述
- 输入格式
- 输出格式
- 样例输入
- 样例输出
- 数据范围
- 测试点列表

要求：

- 标题不能为空。
- 难度不能为空。
- 分类不能为空。
- 题目描述、输入格式、输出格式不能为空。
- 至少需要测试点。
- 至少需要两组样例测试点。
- 测试点输入和输出不能为空。
- 最多 100 个测试点；单个测试点输入输出合计最多 256KB，全部测试点合计最多 2MB。

填写后点击“保存题目”。

选择“选择判断题”后，编程题输入输出和测试点表单会替换为小题编辑器。每道小题需要设置题干、选项、正确答案和正整数分值。判断题固定使用 A=正确、B=错误。

## 3. 如何编辑题目

进入：

```text
/admin/problems
```

题目列表中的“提交”数量是该题的日常刷题总提交次数。点击这个数字会进入：

```text
/admin/submissions?problemId=题目ID
```

进入后可以查看这道题的所有日常刷题提交记录。

在题目列表中找到题目，点击：

```text
编辑
```

修改表单内容后保存。

如果修改了分类，题目会移动到新的分类下，学生端和管理员端分类筛选也会自动更新。

### 调整题目顺序

题目管理页默认使用“自定义顺序”。每道题左侧会显示拖动手柄、当前位置和上移、下移按钮。按住手柄可以在当前页快速拖到目标题目前或后；跨页移动继续使用上下按钮，移动后页面会自动跳到题目所在页。在某个分类中操作时，只会调整该分类内题目的相对顺序。

新建题目默认放在相应题型最前。Markdown 批量导入会把整批题目放在最前，同时保持文档中的题目先后顺序。

管理员还可以选择标题升序、标题降序、最新创建优先或最早创建优先。标题使用中文、英文和数字的自然排序，例如“第 2 题”排在“第 10 题”前。这些模式默认只用于预览；点击“保存当前题序”并确认后，系统会把当前题型或当前分类全部分页的结果保存为一次性自定义题序快照，然后切回“自定义顺序”。以后新增题目仍按新题置顶处理，不会长期自动套用标题或时间规则。

学生和老师都没有排序入口；学生题库、管理员与老师题目练习、组卷搜索都会按管理员保存的自定义顺序展示。

### 调整分类标签顺序

点击分类区域的“调整分类顺序”，可以拖动分类手柄，也可以使用上下按钮排列分类；确认草稿后点击“保存顺序”，点击“取消”则恢复原顺序。编程题和选择判断题分别保存；学生只能看到排序结果，不能自行调整。新分类默认追加到已有分类之后。

## 4. 如何批量下架题目

进入：

```text
/admin/problems
```

使用方式：

1. 在题目列表左侧勾选要下架的题目。
2. 可以点击“全选当前页”。
3. 确认“已选择 N 道题”数量正确。
4. 点击“批量下架”。
5. 浏览器会弹出二次确认。
6. 确认后下架。

注意：

- 只会全选当前页，不会跨页全选。
- 切换分页或分类后，选中状态会清空。
- 下架题目会从日常题库、管理员校题、组卷和专项练习选题中隐藏，学生不能继续提交、试运行或使用 AI。
- 下架不会删除测试点、历史提交和考试关联，学生已经获得的天梯积分会保留。
- 已加入已发布考试或学生未完成专项练习的题目不能直接下架，应先处理对应考试或任务。

## 5. 如何通过 Markdown 导入题目

进入：

```text
/admin/problems/import
```

使用方式：

1. 一次选择一个或多个 `.md` 文件（最多 20 个），也可以直接编辑当前文档文本。
2. 填写默认难度和默认分类，作为兜底。
3. 点击“解析预览”。
4. 按文件检查解析结果，并核对每道题的来源文件、题型、难度、分类、样例数量和数据范围。
5. 确认无误后点击确认导入。

同一批文档可以混合编程题和选择判断题。系统会读取每道题自己的 `## 题型`、`## 难度` 和 `## 分类`；没有 `## 题型` 但包含 `## 客观题` 时自动识别为选择判断题。导入成功后，题目会按各自题型和分类出现在日常题库中。

每次最多选择 20 个文档，每个文档最大 1MB，整批请求最大 8MB。任一文件解析失败时会标明文件名，整批不会进入确认导入，避免只导入一部分。

## 6. Markdown 标准格式

支持一个文件导入一道或多道题。每道题用一级标题 `#` 开始。

推荐格式：

````markdown
# A+B 问题

## 难度

入门

## 分类

基础语法

## 题目描述

输入两个整数 a 和 b，输出它们的和。

## 输入格式

一行两个整数 a 和 b。

## 输出格式

输出一个整数，表示 a+b 的结果。

## 样例

### 输入样例 1

```text
1 2
```

### 输出样例 1

```text
3
```

### 输入样例 2

```text
10 20
```

### 输出样例 2

```text
30
```

## 数据范围

1 <= a, b <= 1000
````

规则：

- 每道题至少两组样例。
- 输入样例和输出样例必须成对。使用编号时必须全部编号、从 1 连续递增；乱序块会按编号配对，重复或缺失编号会拒绝导入。
- 样例内容必须放在代码块中。
- 代码块里的内容才会保存为样例。
- 文件开头允许带 UTF-8 BOM，导入器会自动忽略。
- `## 难度` 和 `## 分类` 可以在 Markdown 中写；如果缺少，则使用导入页面的默认值。
- 当前暂不支持在 Markdown 中设置隐藏测试点、考试分值或题目标签。

编程题的题目描述、输入格式、输出格式、数据范围，以及选择判断题的题干和选项，共用同一套题面富文本渲染。可使用代码块、行内代码、标题、列表、表格、链接、粗体和 KaTeX 数学公式；导入预览与正式做题页的显示规则一致。Markdown 图片只渲染洛谷受信任 CDN 的 `http`/`https` 地址，其他图片语法会按普通文本显示。

选择判断题使用 `## 题型` 和 `## 客观题`。选项必须是单行 `A. 选项内容`，不要写 `A.` 后再另起代码块：

````markdown
# GESP 选择判断标准样例

## 题型

选择判断

## 难度

入门

## 分类

GESP 一级

## 题目描述

请按题号顺序作答。

## 客观题

### 第 1 题

阅读下面代码，判断输出结果。

```cpp
int a = 3;
int b = 4;
cout << a + b << endl;
```

A. 输出 `7`
B. 输出 `34`
C. 编译错误
D. 没有输出

答案：A
分值：2

### 第 2 题

`break` 语句可以终止当前循环。（ ）

A. 正确
B. 错误

答案：A
分值：2
````

选择判断题不需要输入格式、输出格式和样例；每道小题必须有答案和正整数分值。题干可以使用 Markdown 代码块，做题页会渲染为代码样式，不显示原始 ```cpp 标记；选项里需要代码或输出时，用行内代码，例如 `A. 输出 \`7\``。

数学内容使用 LaTeX，行内公式用一对 `$` 包住，独立公式用 `$$...$$`。该规则同时适用于编程题题面和选择判断题题干、选项：

- 次方：`$2^6$`；多字符指数写成 `$2^{10}$`。
- 下标：`$2102_{(3)}$`，显示为带 `(3)` 下标的进制数。
- 分数：`$\frac{1}{2}$`。
- 根号：`$\sqrt{2}$`。
- 不等式：`$1 \le n \le 100$`。

不要直接写 `2102_{(3)}` 或 `2^6` 期待系统自动识别；没有 `$...$` 时它们会按普通文字显示。C++ 代码仍使用行内反引号或 `cpp` 代码块，不要把代码放进数学公式。

维护人员需要重新核对本地已有的 GESP 一级至三级真题时，可先执行只读审计：

```bash
npx tsx scripts/sync-luogu-objective-problems.ts
```

确认输出后再加 `--apply` 更新。脚本以洛谷有题公开原文为准，校验题干、选项、答案、分值和数学公式，只原位更新已存在的正式真题，不创建缺失套题，也不改变题目 ID 和提交关联。

如果需要直接修正 `D:\GESP-md文档\选择判断` 下一级至三级的原始版和标准导入版 Markdown，先只读预检，再显式写入：

```bash
npx tsx scripts/sync-luogu-objective-markdown.ts
npx tsx scripts/sync-luogu-objective-markdown.ts --apply
```

脚本固定核对 41 套真题、82 份 Markdown，写入前会在 `D:\GESP-md文档\backups` 建立逐文件备份；也可用 `--root=绝对路径` 指定其他选择判断目录。题库 Markdown 位于项目仓库之外，不会随网站代码发布或推送到 GitHub。

## 7. 如何创建模拟考试

进入：

```text
/admin/exams
```

点击新建考试，填写：

- 考试名称
- 考试说明
- 考试时长，单位分钟
- 考试类型：编程题考试或选择判断考试
- 考试状态
- 是否开启本场考试 AI 思路

建议新建时使用 `draft` 草稿状态，题目确认后再发布。

一场考试只能加入同类型题目。已有题目时考试类型会锁定；如需修改类型，先移除考试内全部题目。

管理员创建的考试会记录当前管理员为创建者，但管理员仍可查看和维护全平台全部考试。老师创建的考试只对该老师和管理员开放。考试列表会在标题旁显示“出卷人：用户名”；升级前没有归属记录或原创建账号已删除的考试显示“出卷人：未记录”。该标签表示考试创建人/归属账号，不表示最后点击发布的人。

考试 AI 开关只影响学生考试答题页。关闭时学生看不到 AI 按钮，接口也会拒绝请求；选择判断题默认不显示 AI，避免泄露客观题答案。

## 8. 如何添加已有题目到考试

进入考试编辑页：

```text
/admin/exams/[id]/edit
```

使用“添加已有题目”区域：

1. 可以直接点击分类按钮，只展示该分类下的题目。
2. 可以输入题目名称继续搜索。
3. 搜索结果中可以单独勾选题目。
4. 可以点击“全选当前结果”，一次性选中当前搜索结果中还没有加入考试的题目。
5. 设置题目分值。
6. 设置起始排序数字。
7. 点击“添加选中题目”，批量加入考试；也可以在某一道题右侧点击“添加到考试”单独加入。
8. 已经在考试中的题目会标记为“已在考试中”，不能重复加入。

已添加的题目会显示在当前考试题目列表中。

题目搜索会自动限制为当前考试类型。选择判断考试的题目总分由各小题分值合计，不在组卷页手动改分。

## 9. 如何通过 Markdown 导入题目到考试

进入：

```text
/admin/exams/[id]/import
```

使用方式和日常题库 Markdown 导入类似。

导入后：

- 题目会保存到日常题库。
- 测试点会保存到数据库。
- 题目会自动加入当前考试。
- 多题 Markdown 会一次加入多道题。

## 10. 如何发布考试

在考试管理页或考试编辑页点击发布。

发布前系统会校验：

- 考试标题不能为空。
- 考试时长必须大于 0。
- 考试至少包含 1 道题。
- 每道题必须有分值。
- 每道题分值必须大于 0。

发布时系统会固化本场题目的标题、题型、客观题内容和分值快照，后续计分以快照为准。考试已发布后只能切换本场 AI 开关或结束考试，不能修改题目集合、题序、分值或核心信息；尚无学生考试记录时可以先“取消发布”回到草稿再调整，已有记录后不能取消发布。已结束考试不能修改或重新发布。

考试状态说明：

```text
draft      草稿，学生不可见
published  已发布，学生可参加
ended      已结束，学生不可继续答题
```

管理员可以在模拟考试列表中点击“进入做题”，按考试题单逐题检查题面并提交代码或选择判断答案。管理员练习模式不限时，不需要交卷，提交记录计入日常提交，不会创建学生考试记录或影响考试成绩。单大题选择判断练习会隐藏左侧题单以扩大题面；同场多题时仍保留题单用于切题。考试题单和当前题目标题会按当前管理员的历史 Accepted 显示“已通过”，并可快捷查看最近一次通过代码或答案；后续失败不会覆盖这个历史状态。管理员练习页的选择判断标准答案默认隐藏，通过题目标题旁的统一按钮显示或再次隐藏；提交后会在答案区显示逐题对错和自己的答案。独立解析开关开启后，右栏按 AI 解析在上、答案输入在下排列；答案编辑器完整展开并使用主页面滚动，不再产生答案区外层滚动条。学生正式考试答题和考后结果页不会展示客观题 AI 解析；日常刷题仅对已授权且完成一次日常提交的学生逐题开放。代码编辑器与学生端一致，已关闭自动代码提示、Tab 补全、参数提示和内联建议，并支持代码字号调节。答题页会预加载并解码通过提示图，首次 Accepted 也从图片可绘制后再开始短暂动效；图片失败时使用文字反馈。

## 11. 如何查看日常提交记录

进入：

```text
/admin/submissions
```

这里显示所有用户的日常刷题提交。

支持筛选：

- 用户名
- 用户角色
- 题目
- 状态
- 开始日期
- 结束日期

- AI 模型配置分为“编程题”和“选择判断题”两张配置卡；学生端和老师端都不显示模型调整入口。
- 当前暂未开放学生自助注册页，注册开关是预留设置。

### AI 服务商、模型与思考模式

- 系统内置 DeepSeek、豆包/火山方舟和自定义 OpenAI-compatible 三种服务商。DeepSeek 与豆包使用固定官方 Base URL，自定义服务才允许填写地址；编程题和选择判断题可以分别选择服务商。
- API Key 不在管理页面录入。维护人员需要在本地或服务器 `.env` 中分别配置 `DEEPSEEK_API_KEY`、`ARK_API_KEY` 或 `AI_CUSTOM_API_KEY` 并重启服务；页面只显示当前生效服务商的密钥是否已经配置。
- 两张配置卡各自提供“获取可用模型”，读取当前卡片草稿服务商的 `/models`。上游不支持模型列表、或列表里没有目标模型时，可以直接手工填写模型 ID。
- 模型列表可能同时包含图像、向量等非对话模型；请选择支持 OpenAI Chat Completions 的模型。
- 两套配置分别设置思考模式。自定义服务默认不发送 `thinking` 参数；只有确认上游兼容时才选择“发送 thinking 参数”。
- 编程题配置用于学生编程助手、后台编程校题助手及老师、管理员学情摘要；选择判断配置用于学生、老师、管理员共享的选择判断解析。API Key 仍按服务商共用环境变量槽，不按题型重复保存。
- 模型、服务商、地址或思考模式变化后，只会使对应题型配置的缓存失效；另一套配置和缓存不受影响。
- 自定义服务在生产环境只能使用公共 HTTPS。系统会拒绝凭据型 URL、查询参数、片段、本机/内网/保留地址、DNS 私网解析、重定向和超大响应。

### AI 自定义提示词

- “编程题 AI 模型”卡片提供理解题目、下一步提示、检查代码、自由提问四个独立编辑器；“选择判断 AI 模型”卡片提供题目解析编辑器。
- 每项提示词为 1–4000 字。修改或点击“恢复默认”只更新当前页面草稿，必须点击页面底部“保存设置”才会生效。
- 提示词用于调整教学语气、步骤、详略和解释方式，不支持模板变量。题目、学生代码、评测信息、选项和数据库答案由系统自动、安全地加入请求。
- 完整代码与隐藏测试点保护、题面提示词注入防护、数据库标准答案、全部选项解析和 JSON 输出结构均为固定规则，管理员提示词不能覆盖。
- 保存后无需重启。修改某一编程模式只影响该模式的新请求和缓存；修改选择判断提示词后，旧共享解析自动失效。学情看板摘要不读取这些提示词。

### AI 角色触发间隔

- 系统设置可以分别配置学生、老师、管理员的编程入口与选择判断生成/刷新间隔，范围为 5–600 秒。
- 学生选择判断间隔同时用于缓存缺失时的首次生成和主动重新生成；有效共享缓存的普通读取不计时。
- 冷却桶按“账号＋题型配置”隔离；切换题目、学生、考试或按钮不能绕过同一类限制，编程题和选择判断题互不占用间隔。
- 只有真正开始请求上游模型时才计时。有效缓存、幂等重放和调用前配置错误不消耗间隔；上游调用后的超时、错误或结构校验失败仍会计时。

### AI 助手开关

- 日常练习 AI 开关在“系统设置”中全局控制。
- 考试 AI 开关在考试新建/编辑表单中按单场考试控制，默认关闭。
- 每名学生的“编程 AI”和“选择判断 AI”是两项独立个人权限，默认关闭。
- 学生个人权限和日常/考试开关必须同时开启；任一关闭时学生页面隐藏 AI，接口也会返回 403。
- 学生编程助手只支持编程题。学生选择判断解析使用独立主开关、学生总开关和个人权限，并要求先完成当前大题的一次日常提交；考试提交不能解锁，正式考试没有入口。
- AI 提供理解题目、下一步提示、检查当前代码和当前题目自由追问，但不能返回完整代码、可复制代码语句或最终答案。
- 同一学生在所有编程题、考试和 AI 入口中共用管理员设置的学生编程助手间隔，默认 20 秒；服务端返回实际倒计时，前端不再写死固定值。
- 学生端在浏览器中保留最近 20 条消息；服务端保存学生实际看见的提问、清洗后 AI 回复、题目/考试快照、状态、耗时、模型调用次数和 API 返回的 Token 数据。
- 管理员可从“AI 使用”查看今天、近 7 天、近 30 天、全部或自定义时间范围的班级统计，并进入学生明细审阅具体问答。缓存命中计一次学生使用，但模型调用次数和 Token 为 0。
- 服务端不会保存学生代码、客户端历史副本、完整 Prompt、隐藏测试点、完整错误日志或模型内部推理；学生清空本地面板不会删除教师端历史记录。
- “系统设置”可将 AI 对话留存期设为 30、90、180、365 天或永久，默认 180 天；过期清理由 AI 请求和看板访问触发，每天至多执行一次。

### 选择判断题 AI 解析

- “选择判断题 AI 解析”主开关默认关闭；学生还需开启学生总开关和个人选择判断 AI 权限，后台角色不读取学生权限。
- 管理员、老师的题目练习详情和模拟考试练习，以及满足解锁条件的学生日常刷题/专项练习，统一按“解析在上、答案输入在下”排列。长解析可以在 AI 面板内滚动；答案编辑器使用 `360–520px` 响应式高度完整展开，答案区外层不产生横向或纵向滚动条。移动端按自然顺序排列，正式考试及结果页不开放学生解析。
- 页面标题操作区提供“显示答案/隐藏答案”，每次进入或切换题目时默认隐藏全部小题答案；AI 解析按钮不受显隐状态影响。
- 浏览器只提交题目 ID 和小题序号。题干、选项和标准答案由服务端读取，数据库答案始终是最终判定依据，不能由客户端或模型改写。
- 解析按题目小题跨角色共享，学生、老师和管理员都可主动重新生成并覆盖共享版本；非缓存生成和刷新按管理员设置的当前角色间隔限制，同一小题跨角色不能并发生成。
- 解析会在题干、选项、答案、选择判断模型配置或管理员解析提示词变化时失效。生成失败不会覆盖已有解析。
- 学生客观题调用会写入 AI 使用审计并标记客观题与小题序号；缓存读取也计一次使用，但模型调用和 Token 为 0。后台解析不混入学生看板。数据库不保存 API Key、内部推理、完整 Prompt 或上游原始响应。

### AI 使用与对话审阅

```text
/admin/ai-usage
/admin/ai-usage/[studentId]
```

- 总览展示学生使用次数、实际上游模型调用次数、活跃学生、成功率、缓存命中和 Token 总量。
- 今日视图按北京时间展示 24 小时使用分布；学生列表包含未使用过 AI 的学生。
- 明细按题目和对话展示学生可见提问、AI 最终回复、精确时间、响应时长、缓存/失败状态、模型调用次数和 Token。
- 失败原因经过安全化处理，不展示服务器堆栈；题目或考试删除后仍通过标题快照保留历史语境。

## 18. 如何处理 Docker Judge 异常

管理员题目练习和管理员考试练习中的编程题也提供“运行样例 / 自定义输入”。试运行不会写入 `Submission`，不会改变排行榜、错题本、考试成绩或专项练习进度。上线或上课前建议先运行一个公开样例和一个自定义输入，再执行一次正式提交，分别确认试运行和正式判题都正常。

试运行与正式提交共用 Judge 队列，但正式提交优先于尚未开始的试运行。每个账号只能同时进行一个试运行，结束后有 5 秒冷却；频繁点击会返回 429，不代表 Docker 损坏。

若只有“运行样例”不可用而自定义输入正常，先检查题目是否配置了公开样例。样例输入和标准输出只由服务端读取，管理员和学生浏览器都不能自行传入隐藏测试点。

### 学生提交一直失败

先检查 Docker：

```bash
docker info
```

再检查健康接口：

```text
/api/health
```

确认 `.env` 中：

```env
NODE_ENV=production
APP_ORIGIN=https://botcode.work
SESSION_COOKIE_SECURE=true
OJ_LISTEN_HOST=127.0.0.1
JUDGE_MODE=docker
JUDGE_DOCKER_IMAGE=oj-cpp-judge
```

### Docker Judge 不工作

检查容器和镜像：

```bash
docker ps
docker ps -a
docker images
```

重新构建镜像：

```bash
docker build -t oj-cpp-judge ./docker/judge-cpp
```

然后重启服务。

### Docker daemon 没启动

表现：

```text
docker info
```

报无法连接 Docker API。

处理：

- Windows：启动 Docker Desktop。
- Linux：启动 Docker Engine。

### Time Limit Exceeded 很多

可能是：

- 学生代码死循环。
- 题目时间限制太小。
- 服务器资源不足。

可在 `/admin/settings` 中检查默认评测时间限制。

## 19. 数据库误操作怎么办

如果误删题目、用户或考试：

1. 先停止服务。
2. 按时间戳找到本次误操作前生成的备份文件：

```text
backups/
```

3. 用备份数据库替换当前 SQLite 数据库。
4. 重新启动服务。
5. 检查 `/api/health`。

恢复前建议把当前数据库也复制一份，避免二次损坏。

## 20. 复制代码失败怎么办

如果管理端或学生端点击“复制代码”后显示失败，先确认访问地址是正式入口 `https://botcode.work`。现代浏览器在非安全上下文中会禁用 `navigator.clipboard.writeText`。

当前平台已经增加兼容复制方案：HTTPS 或安全上下文优先使用 Clipboard API，公网 HTTP 下 fallback 到 `textarea + document.execCommand("copy")`。如果线上仍然失败，按下面顺序检查：

```bash
grep -n 'execCommand\|isSecureContext' /www/oj/src/lib/copyToClipboard.ts
curl http://127.0.0.1:3000/api/health
```

如果服务器源码没有兼容逻辑，按 `docs/deploy.md` 的常规发布流程在本地 Linux/Docker 构建 standalone 包后上传；不要因为单文件修复就在 2GB 服务器热执行 `npm ci` 或 Next.js 全量构建。

线上已经使用 HTTPS；如果地址栏仍是 IP、HTTP 或 `www` 未跳转到主域名，应按 `docs/deploy.md` 检查 DNS、Nginx 和证书，而不是放宽浏览器安全策略。

## 21. 学生忘记密码怎么办

进入：

```text
/admin/users
```

找到学生账号，点击编辑，在“设置新密码”中填写至少 8 位的新密码并再次确认。可以使用显示/隐藏按钮核对输入；留空保存则不会修改当前密码。

原密码已经不可逆加密，页面、接口和数据库都不能还原显示。不要为了“查看原密码”改成明文或可逆存储。

提醒学生下次登录使用新密码。

学生账号只允许最后一次登录的浏览器会话继续使用；学生在新设备登录时，旧设备会自动下线。若该学生存在进行中的考试，新登录会先结算并交卷。老师和管理员账号允许多设备同时登录。修改任意账号密码或切换账号角色会废除原有会话。

老师端不提供任意密码输入。老师只能点击“重置密码”，确认后把学生密码恢复为 `12345678`，并使学生旧会话失效。

桌面端用户编辑面板会在视口内自适应居中跟随；表单超过视口高度时改为面板内部滚动。点击编辑会回到面板顶部并聚焦用户名，不会强制跳动整个页面；移动端仍按普通上下顺序展示。

## 22. 如何管理学生头衔和天梯榜

进入：

```text
/admin/leaderboard
```

管理员天梯榜顶部展示前三名领奖台，第四名以后展示完整排名。电脑端使用数据表，移动端使用纵向卡片；管理员仍可查看头衔来源、展示头衔、自动段位、段位积分、唯一 AC 题数和 AC 总次数。

当前计分规则：

- 段位积分实时从历史 `Submission` 计算，不写入积分缓存表。
- 每个学生每道题第一次 Accepted 计入唯一 AC 题数，并获得 10 段位积分。
- 同一题多次 Accepted 只算 1 道唯一 AC 题，但会计入 AC 总次数。
- 日常刷题提交和模拟考试提交都会计入统计。
- 排名排序为：段位积分降序 → 唯一 AC 题数降序 → AC 总次数降序 → 用户名升序 → 用户 ID 升序。

如需设置学生自定义头衔，进入：

```text
/admin/users
```

在新增或编辑学生账号时，可以填写“自定义头衔”，并分别开通“编程 AI”和“选择判断 AI”。头衔最多 20 个字，留空则使用系统根据积分计算出的自动段位名；自定义头衔只影响展示文案，不影响段位积分、自动段位和排名。两项权限默认关闭，并继续受各自总开关和使用场景限制。

## 23. 如何使用教师学情看板和下发专项练习

进入：

```text
/admin/learning
```

看板会汇总所有学生近 7 天、近 30 天或全部历史的编程提交。日常练习和考试都会参与诊断；选择判断题不会混入。点击学生后可以查看主要问题、持续卡题、最近失败提交、AI 学情摘要和推荐练习题。

学生列表固定按中文姓名拼音 A–Z 排列，英文用户名按字母排列，数字、符号或无法识别的首字符归入 `#`。可以在搜索框中按用户名即时过滤，也可以点击吸顶的 `A–Z #` 通讯录索引定位到对应分组；搜索只过滤学生卡片，不会改变顶部全体学生统计。切换分析周期会清空本次搜索。

“AI 学情摘要”只把提交数量、错误统计、薄弱分类和持续卡题等后台聚合数据发送给管理员选定的 AI 服务，不发送源码、隐藏测试点、完整错误日志或学生 AI 对话；这些聚合数据不会再以“分类掌握率”或“错误状态分布”模块单独展示。相同数据和同一模型配置会复用数据库缓存；AI 失败时仍可正常查看规则诊断和下发练习。

下发流程：

1. 核对系统推荐题。推荐优先使用待攻克错题，再补充同分类从未尝试题。
2. 使用“全部＋分类”标签配合标题关键词搜索，根据需要删除、添加或调整顺序，每份选择 1–10 道编程题。
3. 填写标题、可选说明和截止日期，然后确认下发。
4. 未归档任务仍可编辑题目集合、顺序、标题、说明和截止日期，所有草稿在一次事务中统一保存；取消会恢复服务器版本。进行中任务需先归档，归档后可永久删除，删除操作不可恢复。管理员可以维护全部任务；老师只能维护自己下发的任务。

需要给多名学生布置同一套课后练习时，进入 `/admin/assignments`：

1. 搜索并勾选 1–100 名学生；“全选当前结果”只作用于当前搜索结果，已经勾选的其他学生会保留。桌面端学生筛选面板会在视口内居中跟随，名单过长时在面板内部滚动；移动端保持普通上下布局。
2. 编排 1–10 道公共编程题，并填写标题、说明和截止时间。
3. 个性化编辑区默认不展示；点击某名已选学生的“个性化”后，页面会自动定位并聚焦该学生的编辑区。可以仅为该学生删除公共题、恢复公共题或增加新题；最终顺序始终为保留的公共题在前、个性化新增题在后。
4. 确认发布后，系统在同一事务内校验全部学生。只要一名学生存在无效题目或与其他未完成任务重复，本批次就不会创建任何任务，页面会定位并标红冲突学生。
5. 全部通过后，每名学生得到独立专项练习；以后从其学情详情分别编辑，不再跨学生同步。页面下方保留最近 50 条全平台发布记录。

管理员新建或保存修改后的专项练习，会在学生下次进入或刷新首页时加入未完成任务汇总提醒。弹窗会显示发布账号、进度和截止时间，学生只能点击“去完成专项练习”；点击后相同任务版本静默 60 分钟，期间刷新或重新登录不会重复弹出。满 60 分钟后仅在学生首页重新读取状态并按未完成情况提醒；新任务或再次修改会在下一次首页读取时立即触发。系统不做实时推送，也不会在做题、考试或专项练习页面打断学生。

同一道题不能同时出现在该学生两份未完成任务中。删除已完成题时系统会强提醒；确认后只解除对应提交的任务关联并重新计算进度，不删除提交、代码或题目。已完成任务新增未完成题后会重新显示为进行中，新题不会继承历史 AC。

只有学生从专项练习入口进入并重新提交 `Accepted` 才计入完成；普通日常提交、考试提交和下发前的历史 AC 均不抵扣。如果评测期间该题被教师移出任务，提交仍会保存为普通练习并提示不计入专项进度。没有自动推荐时，教师可以在练习创建器中搜索现有编程题并手动添加。

## 26. 常用命令

安装依赖：

```bash
npm install
```

本地构建：

```bash
npm run build
```

常规发布优先参考 `docs/deploy.md`，在本地 Linux/Docker 环境生成 standalone 包后上传。只有必须在 2 核 2GB 服务器上构建时，才使用下面的低内存兜底命令：

```bash
pm2 stop oj
NEXT_TELEMETRY_DISABLED=1 NEXT_PRIVATE_BUILD_WORKER_COUNT=1 NODE_OPTIONS='--max-old-space-size=768' npm run build
pm2 restart oj --update-env
curl http://127.0.0.1:3000/api/health
```

启动生产服务。`npm run start` 会先检查生产环境变量、预加载 `.env`，再启动 standalone 服务；不要绕过它直接裸跑 standalone server。

```bash
npm run start
```

检查生产环境变量：

```bash
npm run check:env
```

应用数据库迁移：

```bash
npm run db:deploy
```

查看迁移状态：

```bash
npm run db:status
```

修改管理员密码：

```bash
npm run admin:password -- admin 新密码
```

备份数据库：

```bash
npm run backup:sqlite
```

运行质量检查：

```bash
npm run test
npx tsc --noEmit
npm run lint
npm run build
```
