# 问题反馈功能说明

## 入口与权限

三种角色均从“天梯榜”右侧的“问题反馈”进入。学生与老师使用提交表单和自己的记录；管理员进入反馈管理。学生正式考试仍使用锁定布局，不增加普通导航。

| 角色 | 页面 | 权限 |
| --- | --- | --- |
| 学生 | `/student/feedback` | 提交、查看自己的原文、截图和回复 |
| 老师 | `/teacher/feedback` | 同上，不能看学生或其他老师的反馈 |
| 管理员 | `/admin/feedback` | 查看全部、筛选、回复与变更状态，不代提交 |

各页面的 `/[id]` 子路径为详情。未登录跳转登录页；详情归属在服务端核验，越权和不存在均返回 404。第一版不提供反馈编辑、删除、追加追问、匿名提交或通知。

## 操作与数据流

提交人填写标题和描述、选择可选截图 → 服务端校验登录与同源请求 → 预留提交槽 → 限量读取与校验图片 → 单事务创建反馈及附件 → 返回详情 ID。校验或写入失败不留下部分数据，提交槽在结束时释放。

新反馈为 `pending`（待处理）。管理员回复时，在一个事务中追加 `FeedbackReply` 并改为 `resolved`（已处理）；也可单独标记已处理或重新打开。已有回复不被覆盖。提交人重新打开详情时读取最新状态，没有实时推送。

网络失败时客户端保留当前填写内容并恢复按钮；超时可能发生在服务端已经保存之后，应先核对列表再重试。未提交内容不写入 localStorage，也不会在刷新后恢复。列表固定每页 20 条，按创建时间、ID 倒序排列；管理员默认只看待处理。

## 数据模型与截图

| 模型 | 保存内容 |
| --- | --- |
| `Feedback` | 提交人可空关联、用户名和提交时角色快照、标题、描述、状态、时间 |
| `FeedbackAttachment` | 反馈关联、顺序、WebP 二进制、尺寸和字节数 |
| `FeedbackReply` | 反馈关联、管理员可空关联及用户名快照、回复和时间 |

账号删除使用 `SET NULL` 保留历史快照。列表只读取计数和元数据；详情不含图片二进制，图片由独立鉴权接口读取。角色或会话失效时旧图片链接也不能继续请求。正文和回复按纯文本显示，不执行 HTML。

上传限制由服务端独立执行：

- 标题 1–100 字，问题描述 1–5000 字，回复 1–3000 字，去除首尾空白。
- 最多 3 张静态 PNG / JPEG / WebP，原文件每张最多 5 MiB，整个 multipart 请求最多 16 MiB。
- 在解析前按真实读取量截断超限请求，不能依赖 `Content-Length`；读取超时 30 秒。
- 图片真实格式须匹配 MIME，拒绝动画（含 APNG）、损坏图片及超过 1600 万像素的图片。
- `sharp` 自动校正方向、限制最长边 1920 像素、不放大，输出 quality 80 的 WebP；移除元数据，单张输出超过 1 MiB 则要求裁剪重试。
- 同账号仅一个在途请求，成功保存后冷却 30 秒；失败不占冷却。当前单进程最多同时处理两个上传，每条请求内逐张转换。进程重启会清空内存冷却记录，多实例前需统一限流状态。

图片不放入 `public`，也不经过 Next 图片优化代理。所有反馈 API 设置 `Cache-Control: private, no-store` 和 `X-Content-Type-Options: nosniff`；日志不输出正文、图片或包含表单数据的数据库异常。

## API

以下接口均使用站内会话 Cookie，写入须带合法 `Origin` / `Referer`。

| 方法与路径 | 输入与返回 | 权限 |
| --- | --- | --- |
| `POST /api/feedback` | multipart：`title`、`content`、重复的 `attachments` 文件；201 返回 `{ id }` | 学生、老师 |
| `GET /api/feedback?page=1` | 返回 `{ items, pagination }`，只含本人记录 | 学生、老师 |
| `GET /api/feedback/[id]` | 原文、截图元数据、回复列表 | 本人或管理员 |
| `GET /api/feedback/[id]/attachments/[attachmentId]` | WebP 图片，不可公开缓存 | 本人或管理员，同时核验附件所属反馈 |
| `GET /api/admin/feedback` | `page`、`status=pending\|resolved\|all`、`role=student\|teacher\|all`、`q`；返回分页列表 | 仅管理员 |
| `PATCH /api/admin/feedback/[id]` | JSON `{ status: "pending" \| "resolved" }`；返回 `{ ok: true }` | 仅管理员 |
| `POST /api/admin/feedback/[id]/replies` | JSON `{ content }`；追加回复并置已处理，201 返回 `{ ok: true }` | 仅管理员 |

错误统一为 `{ error }`：400 为格式或字段错误，401 为未登录/会话失效，403 为角色或来源不合法，404 为不存在/不可读，408 为上传读取超时，413 为请求过大，429 为账号并发/冷却限制，503 为上传服务繁忙。429 和 503 附带 `Retry-After`；内部错误只返回安全的 500 提示。

## 迁移、备份与验证

迁移 `0019_problem_feedback` 只新增三张表及索引，不改旧业务数据。已有数据库应备份后使用 `npm run db:deploy`；`db:init` 和 `seed` 只适用于允许清空数据的本地环境。

截图随 SQLite 一起备份和恢复，每条反馈最多增加约 3 MiB 图片数据，应观察数据库与备份的磁盘增长。没有新增环境变量或公开上传目录。`sharp` 使用锁定版本的直接依赖；部署仍须使用兼容生产机的 Linux standalone 构建，不能上传 Windows 原生依赖。回退旧应用时保留新增表，不主动删除反馈。

验证入口：`npm run test` 包含上传边界、真实会话/API 权限、事务回滚、18→19 迁移、初始化结构一致性和附件备份恢复；`npm run test:e2e` 覆盖三角色闭环、失败重试、手机布局、菜单顺序和原有正式考试锁定回归。E2E 截图位于忽略目录 `tmp/feedback-qa/`，不含真实用户数据。
