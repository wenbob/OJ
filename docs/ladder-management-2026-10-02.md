# 管理员天梯积分与段位管理（2026-10-02）

管理员入口为 `/admin/leaderboard/settings`，从管理员天梯榜的“积分与段位设置”链接进入。学生和老师没有管理入口，全部新增接口要求 `admin` 权限。

## 功能与计分

页面包含学生积分、段位门槛、调分记录三个页签，沿用现有展示组件与八档徽章。学生搜索和记录搜索均服务端分页，每页默认 20 条。

总积分为唯一历史 Accepted 题数 × 10，加奖励流水与管理员调分流水。管理员可加分、扣分、设定总分；设定总分转为当次差额，不限制以后做题获得积分。总分不得低于 0。调分理由去除首尾空白后为 1～200 个字符，流水只追加，理由和操作者只在管理员界面与接口中返回。

段位名称、顺序和图标固定，默认门槛依次为 0、65、130、260、455、715、1040、1560。青铜固定为 0，其余门槛必须严格递增。学生首页、导航徽章、三端排行榜、晋级进度和成长路径共用配置，单次页面渲染内去重读取，不跨请求缓存权限或配置。

根据用户后续要求，学生天梯页移除了计分公式、抽奖说明和相关鼓励话术，不再展示原先“基础分 + 奖励分”的拆分行；排名、总分、段位和晋级进度保留。

## 操作说明

1. 用管理员账号进入“天梯榜”，点击“积分与段位设置”。
2. 在“学生积分”搜索用户名，点击对应学生的“调分”。
3. 选择加分、扣分或设定总分，填写分数和理由，核对积分与段位预览后保存。例如原有 100 分，设为 80 分时记一条 −20 分记录，以后通过新题仍可获得 10 分。
4. 如果提示积分已经变化，核对页面刷新后的积分与保留的输入，再次保存。网络结果未确认时可按原输入重试，同一请求不会重复计分。
5. 在“段位门槛”修改最低积分并整体保存；青铜固定为 0。若提示其他页面已修改，点击“重新加载门槛”，核对最新配置后再编辑保存。
6. 在“调分记录”按学生用户名和操作类型筛选。已保存的记录不能直接修改或删除，纠错应提交新的反向调分，并说明原因。

刷新学生首页或任一角色的天梯榜后可看到新的积分与段位。调分明细、理由和操作者只对管理员开放。

## 数据与接口

增量迁移为 `0023_ladder_point_management`，同步维护 Prisma schema 与初始化 SQL；本地实际数据库使用增量迁移，不运行初始化或 seed。

- `StudentPointAdjustment` 保存模式、输入值、实际增减值、调整前后积分、理由、身份快照、唯一 requestId 与创建时间。账号关联删除时置空，ID 和姓名快照继续保留。
- 独立 `SystemSetting.__ladderTierConfig` 保存八档门槛和 revision，不进入旧系统设置全量保存字段。查询失败或已存配置损坏时不会静默恢复默认；仅查询成功且缺行时使用默认值。
- 积分读取通过数据库聚合，调分与奖励分开汇总，无总积分缓存表。账号目录只聚合当前页学生，不读取全站 Accepted 明细。

| 方法与路径 | 行为 |
| --- | --- |
| `GET /api/admin/ladder/settings` | 读取段位配置与 revision |
| `PUT /api/admin/ladder/settings` | 提交 `{ revision, minPoints }`，八个门槛一起保存 |
| `GET /api/admin/ladder/students` | 支持 `q`、`page`、`pageSize`，返回学生积分来源 |
| `POST /api/admin/ladder/students/[id]/adjustments` | 提交 `{ mode, inputPoints, expectedPoints, reason, requestId }`，模式为 `add` / `deduct` / `set` |
| `GET /api/admin/ladder/adjustments` | 支持 `q`、`mode`、`studentId`、`page`、`pageSize`，返回私有调分流水 |

相同请求标识重放必须匹配管理员、学生、模式、输入分数、预览积分及理由；匹配时返回原记录，不再次计分。过期预览积分和过期配置 revision 返回 409；无变动不新增流水。写接口沿用本站来源检查与请求大小限制，事务内重新验证角色、当前积分和下限。数据库忙时有限重试，耗尽返回可重试的 503。
